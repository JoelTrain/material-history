## PostgreSQL PVC permissions and health checks

The generated PostgreSQL Deployment has been patched for restricted Kubernetes installations:

- PostgreSQL runs as UID/GID **999** (the official Debian PostgreSQL 17 image user), with `allowPrivilegeEscalation: false` and all Linux capabilities dropped.
- Pod-level `fsGroup: 999` and `fsGroupChangePolicy: OnRootMismatch` request volume group access without a privileged `chown` init container. **Your CSI storage driver must support fsGroup or supply equivalent permissions.**
- The PVC is mounted at `/var/lib/postgresql/data`, while `PGDATA` points to `/var/lib/postgresql/data/pgdata`. The PostgreSQL process creates/owns this subdirectory and sets its required restrictive permissions.
- A startup probe allows up to **five minutes** for initialization; readiness and liveness checks start only afterward. Probes use the configured database name and username.

### Important: existing data directories

**Do not apply this change blindly to an existing PostgreSQL data volume.** An existing volume with `PG_VERSION` at `/var/lib/postgresql/data/PG_VERSION` has its database at the volume root, whereas this deployment uses the `pgdata` child. Switching without moving/restoring the database would make the server initialize a new empty cluster in the subdirectory, hiding old records. Back up, inspect, and migrate/reconfigure the data directory before rollout; do not delete the PVC.

To check pod events and previous logs:

```sh
kubectl -n material-history-postgres describe pod -l app.kubernetes.io/name=db
kubectl -n material-history-postgres logs deployment/db --previous --tail=100
```

If the storage driver ignores `fsGroup` or disallows `chmod`, correct the PVC/storage-class permissions through your cluster storage administrator. The chart deliberately avoids a root or privileged init container that may be prohibited in UDS.

**These files are generated outputs from Compose Bridge.** Re-running the conversion may overwrite manual Helm changes. Preserve this security-context/probe patch in the conversion pipeline or reapply it after regenerating the chart.

The autogenerated `db-environment` ConfigMap currently contains `POSTGRES_PASSWORD` in plaintext. Move database credentials to a Kubernetes Secret before deploying actual sensitive data.
